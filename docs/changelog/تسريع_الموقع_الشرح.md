## السبب الجذري
**الشعار وحده كان أثقل من كل شي** — ملف PNG بأبعاد 789×973 (738KB) بينما يُعرض داخل إطار لا يتجاوز 96px في الواجهة. وفوق هذا كاشه ساعة وحدة فقط، يعني المستخدم يعيد تحميله كل ساعة. أما CSS وJS وAPI فكانت أصلاً مضغوطة ومقسّمة باحتراف (ما انلمست).

## التعديلات (3 ملفات فقط — صفر تغيير على أي كود برمجي)
| الملف | التغيير | الأثر |
|---|---|---|
| `public/logo.png` | تصغير إلى 512×631 + ضغط لوحة ألوان بجودة عالية (Lanczos + palette q92) | **738KB ← 67KB (−91%)** — والدقة تكفي لطباعة الفواتير بوضوح 300dpi |
| `index.html` | إضافة `<link rel="preload" as="image" href="/logo.png" fetchpriority="high">` | الشعار (أكبر عنصر بشاشة الدخول) يبدأ تحميله لحظة قراءة HTML بدل انتظار إقلاع React — يسرّع أول رسمة بثانية أو أكثر على الشبكات البطيئة |
| `firebase.json` | قاعدة كاش جديدة للصور `**/*.@(png|jpg|jpeg|webp|svg|ico)` بمدة 24 ساعة | الزائر العائد ما يعيد تحميل الشعار والأيقونات كل ساعة |

## النتيجة (مقاسة بعد النشر)
- حجم أول تحميل: **~1.32MB ← ~0.65MB (أخف بالنصف)**

- حزم assets ما زالت `immutable` سنة كاملة ✅ (ما انكسرت)
- `firebase-messaging-sw.js` (الإشعارات) بنفس ترويساته تماماً ✅
- بصمات حزم JS لم تتغير إطلاقاً = صفر تعديل بالكود البرمجي ✅

## ما لم يُلمس (عمداً)
الإشعارات والدفع وserver.ts وCloud Run وقواعد Firestore — ولا انرفع شي على GitHub.

## فرصة مستقبلية (اختيارية — تحتاج قرارك)
بيانات الإقلاع API (250KB مضغوطة) هي أكبر مكوّن متبقٍ الآن — تخفيفها يتطلب تعديل منطق السيرفر (تقليل الحقول في `profile=boot`)، وهذا خارج نطاق «بدون لمس السيرفر» الحالي.
