# زر «تشغيل فحص التنبيهات» داخل اللوحة — الشرح

## الطلب
بديل داخل لوحة التحكم عن زر Force run في كونسول قوقل، بأسهل شكل ممكن.

## الملفات المعدلة (2 + ملف مستعاد)
| الملف | التغيير |
|---|---|
| `server.ts` | إضافة مسار واحد: `POST /api/push/run-alerts-admin` محمي ببوابة هوية الأدمن الموجودة أصلاً (Firebase ID token + قائمة المصرح لهم) — يستدعي **نفس** معالج المؤقّت `alertsRunHandler` حرفياً. صفر تغيير بمنطق الإرسال ومنع التكرار |
| `src/components/GeneralSettings.tsx` | زر «تشغيل فحص التنبيهات» (أزرق) بجانب «فحص الآن» في قسم إشعارات النظام + رسالة نتيجة واضحة، ويحدّث سجل «آخر الإشعارات» بعد الفحص |
| `Dockerfile` | ملف مستعاد كما هو من GitHub (كان ناقصاً بالنسخة المحلية) — لزم للنشر، بدون أي تعديل عليه |

## الأمان
- النقطة الجديدة ترفض أي طلب بدون تسجيل دخول أدمن/شريك (مجرّب: ترجع 401)
- مسارات المؤقّت القديمة بقيت كما هي بدون أي تغيير
- الضغط المتكرر آمن 100%: سجل منع التكرار الذرّي يمنع أي إرسال مزدوج — الزر يكمّل النواقص فقط

## التحقق (تم فعلياً بعد النشر)
- ضُغط الزر من اللوحة الحية كأدمن: ظهرت رسالة «تم الفحص — لا توجد تنبيهات ناقصة» ✅
- فحص جاف عبر مسار المؤقّت: نجح بنفس النتيجة ✅
- جسر الواتساب: نبضه استمر بدون انقطاع خلال وبعد النشر (آخر نبضة بفارق ثوانٍ) ✅
- صحة السيرفر والدفع والإشعارات: المسارات كلها سليمة، صفر أخطاء ✅

## ملاحظة أمنية مسجلة (بانتظار قرارك — لم أغيّر شيئاً)
سر مسار المؤقّت `ADMIN_TEST_SECRET` قيمته الافتراضية الضعيفة `123456`. الخطر محدود (منع التكرار يمنع أي إزعاج فعلي) لكن وضع «فحص جاف» يكشف أرقام فواتير معلقة ومبالغها لمن يخمّن السر. الحل دقيقتان بدون كود: تغيير قيمة المتغير في Cloud Run + تحديث هيدر المهمة في Cloud Scheduler بنفس القيمة الجديدة.
